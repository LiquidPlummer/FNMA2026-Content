# The Standard Pitch

Every introduction to AWS opens with the same set of claims. We are going to state them once, in full, because they are genuinely why organizations move to a cloud provider — and because stating them plainly now means we never have to reach for them again.

---

## The Claims

**Global reach.** AWS operates data centers in dozens of geographic locations. Deploying an application near users in Frankfurt or Sydney is a configuration choice rather than a construction project.

**Pay-as-you-go billing.** Resources are billed for the time they exist and the work they do. A server running for three hours costs three hours.

**No up-front capital expense.** There is no hardware purchase, no data center lease, no three-year depreciation schedule. Spending starts at zero and tracks usage.

**Elastic capacity.** The number of servers, the size of a database, the throughput of a queue — all of these can change while the system is running, in minutes, by API call.

**High availability.** AWS operates redundant facilities and offers services designed to survive the loss of a data center.

**Managed services.** For many workloads, AWS runs the operating system, the patching, the backups, and the failover, so that a team can run a database without employing a full-time database administrator.

---

## Why This Is Worth Stating

These claims are the reason the industry moved. Rejecting them wholesale would be as wrong as accepting them wholesale. A team that provisions a load balancer in four minutes and deletes it an hour later, paying for one hour, is genuinely doing something that was not possible with owned hardware.

The problem with the pitch is not that it is false. The problem is that it describes the best case as though it were the default, and it is written to be repeated rather than examined.

So we will examine it — once, in the next note — and then move on.

---

## Key Takeaways

- The standard pitch is: global reach, pay-as-you-go billing, no capital expense, elastic capacity, high availability, and managed services.
- These claims are the actual reason cloud adoption happened, and they are not fabricated.
- They describe a best case, not a default outcome.
- **This is the last note in this material that uses vendor framing.** After the next note, everything is described as a mechanism, a constraint, a cost, or a decision.
